## Overview

Write the agenda for owners who have not seen this request or this scope. Assume they will do their job well once they know the exact interface and the exact acceptance check, and that they will make a reasonable choice wherever the agenda leaves one open. What they cannot know is what you decided: which deliverables, which names, which values from the CEO request, which checks prove each item. Document those. Give them the whole agenda as bite-sized items. DRY. YAGNI. Verify before lock. Lock often.

## Scope Check

If the request covers multiple independent subsystems, it should have been broken into sub-projects during brainstorming (scope phase). If it wasn't, keep this Board to ONE subsystem and say which others need their own Board — one agenda per subsystem. Each agenda should produce a working, checkable deliverable on its own.
